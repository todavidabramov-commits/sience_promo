# СанЭпидЭксперт — корпоративный сайт органа инспекции

[Русский](README.md) · [English](README.en.md)

B2B-сайт экспертного центра **«СанЭпидЭксперт»**: санитарно-эпидемиологическая экспертиза, санитарно-защитные зоны, оценка риска здоровью населения. Публичный фронтенд, CMS на Payload и заявки, которые уходят в админку.

Репозиторий: [todavidabramov-commits/sience_promo](https://github.com/todavidabramov-commits/sience_promo)

---

## Зачем этот сайт

Закрывает запрос промышленного и девелоперского заказчика: понять компетенции центра, выбрать услугу, посмотреть реализованные проекты и нормативку, отправить техническое задание. Каталоги страниц сверстаны по макету и читаются сразу; при необходимости контент переводится в Payload без смены вёрстки.

## Возможности

### Публичный сайт

- **Главная** — cinematic 3D-молекула (React Three Fiber), счётчики, направления, отрасли, проекты и заявка.
- **О компании** — научный фундамент, история центра, аккредитации; декоративная метка с точной копией логотипа.
- **Услуги** — 9 направлений с отдельными страницами: суть, состав работ, порядок из четырёх шагов (включая ожидаемый результат).
- **Проекты** — фильтр по отраслям и подробные материалы по СЗЗ / риску / ПАТ.
- **Эксперты** — кадровый совет в типографике без стоковых портретов и сценарий сборки рабочей группы.
- **Публикации** — избранный материал, поиск, фильтры-бейджи, карточки статей и дайджест.
- **Документы** — реестр нормативов с поиском, фильтрами и скачиванием файлов.
- **Контакты** — каналы связи, реквизиты, Яндекс.Карта с пульсирующей точкой цвета логотипа.

### Интерактив и заявки

- Маски телефона `+7 (___) ___-__-__` и валидация форм на **yup + react-hook-form**.
- Заявки на расчёт, документ и дайджест уходят в Payload (`form-submissions` + загрузка файлов в `media`).
- Поиск по публикациям и документам с подсветкой совпадений.
- Scroll-reveal, кольцевые анимации секций, адаптив: 3D на десктопе, упрощённый hero на мобильных.

### CMS

- **Payload 3**: услуги, проекты, эксперты, публикации, документы, страницы, заявки, медиа, настройки сайта, шапка и подвал.
- Интерфейс админки — **русский / английский**. В `/admin` свой переключатель (как на сайте); cookie `payload-lng` общая, поэтому язык панели и публичного сайта остаются согласованными.
- Контент локализован отдельно: у записи две версии — **Русский** и **English**. В шапке админки переключатель «Язык контента» и подсказка. Незаполненные поля выбранного языка на сайте берутся из русской версии. Автоперевода нет: каждую версию заполняют и сохраняют самостоятельно (или копируют через «Скопировать в другой язык»).
- **Live Preview**: услуги, проекты, публикации, эксперты, документы, страницы, а также настройки, шапка и подвал. Превью открывает соответствующий маршрут сайта с `?lng=` текущей языковой версии. Текст в iframe обновляется сразу при вводе; фото эксперта, обложки проектов и публикаций и файл документа — тоже (по ID медиа подтягивается URL). В админке грузить нужно поля **Фото** / **Обложка** / **Файл**, а не текстовый «Путь к …». На Vercel работает так же: URL относительные.
- Стартовый контент — в `src/lib/content.ts` и `src/i18n/en-catalog.ts`. В базу его переносит `npm run seed`.
- Готово к продакшену на **Vercel Postgres (Neon)** и **Vercel Blob**.

- **Не «витрина из десяти блоков»**, а полноценный отраслевой сайт с внутренними страницами услуг, статей и документов.

- **Рабочие сценарии сразу**: поиск, маски, карта, формы — без откладывания на второй этап.
- **Современный стек** Next.js 16 + Payload 3 + Postgres, без легаси-админок и самописного бэка.

## Локальный запуск

Нужны Node.js 20+ и PostgreSQL. Локальную базу поднимает Docker:

```bash
cd sience-promo
cp .env.example .env
docker compose up -d
npm install
npm run dev
```

Открыть [http://localhost:3000](http://localhost:3000). Админка: [http://localhost:3000/admin](http://localhost:3000/admin). Первого пользователя создаёте в админке при первом входе — сид его не создаёт.

Наполнить CMS русским и английским контентом:

```bash
npm run seed
```

Повторно перезаписать контент: `npm run seed -- --force`. Починить глобалы (шапка, подвал, настройки): `npm run seed -- --repair`.

В `.env` задайте как минимум:

```env
PAYLOAD_SECRET=длинный-случайный-секрет
POSTGRES_URL=postgresql://postgres:postgres@127.0.0.1:5432/sience_promo
NEXT_PUBLIC_SERVER_URL=http://localhost:3000
```

Опционально:

- `BLOB_READ_WRITE_TOKEN` — загрузки в Vercel Blob;
- `NEXT_PUBLIC_YANDEX_MAPS_API_KEY` — ключ JS API карт (без ключа карта на контактах всё равно пробует загрузиться).

## Деплой на Vercel

1. Репозиторий подключён к Vercel (root directory — корень приложения).
2. В проекте Vercel: **Postgres** (Neon) и **Blob**.
3. Переменные: `PAYLOAD_SECRET`, `POSTGRES_URL`, `BLOB_READ_WRITE_TOKEN`, `NEXT_PUBLIC_SERVER_URL`.
4. Сборка: `npm run ci` (`payload migrate` + `next build`).

После деплоя проверьте главную, внутренние страницы услуг, отправку формы, `/admin`, live preview записи и обе языковые версии контента.

## Языки

Два независимых слоя.

**Язык интерфейса.** На сайте и в админке переключатели **RU / EN**. Оба пишут cookie `payload-lng`: меняется язык публичных подписей и панелей Payload, не содержимое записей. Если cookie ещё нет, язык берётся из `Accept-Language`: русский и страны СНГ — русский, иначе английский.

**Язык контента.** Поля коллекций и глобалов хранятся отдельно для `ru` и `en` (`localization` в Payload, язык по умолчанию — русский, fallback включён). В админке это центральный переключатель «Язык контента». Live Preview передаёт выбранную версию параметром `?lng=` и не подменяет cookie посетителя.
